# STREMDBC Management API

The management API is served by the HTTP listener together with the optional
dashboard and static HLS/LL-HLS directories. The default base path is
`/api/v1`; both it and the metrics path can be changed in configuration.

## Health and observability

### `GET /health`

Returns process health, version, uptime, configured API/metrics paths, and
whether authentication is enabled. A successful response means the HTTP
process is serving; it is not proof that an external media engine is available.

### `GET /ready`

Returns HTTP readiness. Required external dependencies are checked during
startup before the process reports successful startup.

### `GET /metrics`

Returns Prometheus text exposition at the configured metrics path. The endpoint
is disabled when `metrics.enable` is false.

### `GET /api/v1/info`

Returns service version, Go runtime, CPU, goroutine, and uptime information.

### `GET /api/v1/stats`

Returns registry telemetry and statistics from enabled library components:

```json
{
  "streams": 2,
  "live_streams": 1,
  "viewers": 15,
  "goroutines": 24,
  "memory_bytes": 12582912,
  "uptime_seconds": 390,
  "components": {}
}
```

## Streams

### `GET /api/v1/streams`

Lists registered streams. Stream IDs are restricted to URL-safe ASCII letters,
digits, `.`, `_`, and `-`.

### `POST /api/v1/streams`

Creates an idle stream record. The body must be one JSON object with no unknown
fields or trailing JSON values:

```json
{"id":"camera-01","name":"Camera 01"}
```

### `GET /api/v1/streams/{id}`

Returns a stream snapshot.

### `DELETE /api/v1/streams/{id}`

Deletes an idle stream. Live, recording, or viewed streams return `409` and
must be stopped before deletion.

## Authentication

When `auth.enable` is true, mutating management requests and token issuance
require the configured `X-API-Key`. Anonymous playback does not grant
management permissions.

### `POST /api/v1/auth/token`

Creates a stream-scoped JWT. The request requires one API key and must contain
one of the actions `publish` or `play`:

```json
{"stream_id":"camera-01","action":"play"}
```

JWTs are HS256 tokens issued by `stremdbc`, include an expiry, and are bound to
the requested stream/action. Tokens generated by this service also carry the
requesting client IP and are checked against it during playback/control
authorization.

## Static delivery

When configured by the executable, the HTTP plane serves:

- `/dashboard/` — zero-build management UI
- `/player/{streamID}` — built-in player
- `/hls/{streamID}/...` — files written by the HLS library component
- `/llhls/{streamID}/...` — files written by the LL-HLS library component

Static files are path-checked, and playback paths require a play token when
anonymous playback is disabled. The executable does not automatically connect
an ingest adapter to these writers; an empty directory is not a live stream.

## WebRTC control endpoints

The optional WebRTC adapter exposes standards-shaped control endpoints:

```text
POST   /whip/{streamID}
DELETE /whip/{streamID}/{sessionID}
POST   /whep/{streamID}
DELETE /whep/{streamID}/{sessionID}
```

SDP offers may use `application/sdp` or the JSON compatibility shape
`{"type":"offer","sdp":"..."}`. The current adapter negotiates peer
connections and detects publisher tracks, but does not forward RTP tracks to
viewers. It must not be presented as a complete WebRTC media service.

## Error format

JSON API errors use one `error` field:

```json
{"error":"unauthorized"}
```

Typical status codes are `400` for malformed input, `401` for authorization
failures, `404` for missing resources, `405` for unsupported HTTP methods,
`409` for state conflicts, `500` for internal failures, and `503` when a
requested subsystem is disabled.

## Production checklist

- Enable authentication and inject a random JWT secret of at least 32 characters.
- Use long, unique API keys and set `auth.allow_anonymous: false`.
- Restrict CORS to exact trusted origins.
- Put TLS and a trusted proxy in front of the management plane, or enable the relevant protocol TLS configuration.
- Keep media adapters disabled until a real media engine and end-to-end integration are installed.
- RTMP/RTSP ingest cannot be enabled alongside authentication until their publish-token handshake is implemented; this is rejected during config validation.
- Keep WebRTC disabled until `GO-2026-4479` in the Pion DTLS dependency is resolved or formally accepted with compensating controls; the current vulnerability scan reports no upstream fixed version.
- Validate third-party interoperability, soak/load behavior, backups, and secret rotation in the target environment.
